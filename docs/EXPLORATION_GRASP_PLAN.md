# 受限腕部相机探索与多目标抓取方案

2026-11-16。第一版核心与离线预览已实现，尚未实现整车闭环。抓取入口已支持显式选择多目标中的一件。

## 第一版操作

- `python explore_demo.py`：无硬件演示目标编号、最近目标锁定、遮挡停车请求及栅格覆盖下一步规划；输出 exploration_output/latest.json。
- `python explore_demo.py --replay frames.json`：回放固定坐标系观测；输入为JSON数组，每项含stamp（秒）、origin_m（三维）、observations（name及position_m）。同一文件所有位置必须在同一固定坐标系。
- `python debug.py approach`：现有窗口给有深度拟合的目标编号并显示水平距离，默认选择最近一件，Tab切换目标，再按P/G/D或A。运动期间锁定原目标。原单目标输入兼容。未拟合目标显示depth?，暂不具备持久二维身份。
- 当前实时编号在机械臂底座坐标系内成立，适用固定底盘；移动底盘前需要接入带时间戳的定位和安装外参。配置框架为camera_profiles/exploration.json。
- exploration.py的ScanEnvelope只接受已配置的有向边；目前示教表为空。PreviewTransport仅输出意图。停靠求解、实际扫描/底盘执行、抓取结果自动回写和墙面多高度覆盖仍是下一阶段接口。

雷达地图输入约定0空闲、1障碍、-1未知，分辨率米，原点用于地图接入。CoverageGrid先膨胀底盘净空，再在起点连通区域内按交替行顺序选择未观察单元，经四邻域搜索生成可通行路径；摄像头观察使用方向、视角、有效距离及遮挡射线。该简化二维覆盖用于首版验证，不等于完整洞穴三维视域证明，实际地图需先转换此约定并提供相机地面投影。

## 依据和现状

参考本项目 XH-202605.md 对赛规、答疑的整理：目标可位于地面及低于500mm岩壁，单场3～10个，洞内需要车载照明。地面与岩壁不能共用固定桌面抓姿。原始赛规位于 D:/Lab/挑战杯/LunarRover_HUST-master/docs/project_info/，本轮未重新逐页核验。

当前 live_approach.prepare/start_auto 要求一个检测和一个几何候选；geometry_tracking.py 是相机坐标下短时稳定性检查，不能承担移动相机的持久目标身份。原车工程已有 active_search、frontier_explorer、target_localizer，可评估复用，但不是已接通M3-S。

## 任务流程

探索区域 → 底盘停车、机械臂按示教路径扫描 → 更新目标表 → 选择最近目标并锁定ID → 规划停靠点 → 底盘接近且机械臂有限跟踪 → 停车重新观测 → 锁定抓取坐标 → 沿已验证路径抓取 → 示教放块及反向返回 → 更新目标表再选下一件。

全局洞穴探索与局部机械臂扫描分开：有限视野看不到的区域仍是未知区域，不能因当前无检测就判定区域已清空。全局探索沿用底盘定位/障碍地图，不能仅用目标框决定车辆能否通行。

## 目标表与选择

每个目标持久记录 id、类别、固定坐标系位置及不确定度、最后观测时间、外观特征、观测视角、几何抓姿、状态（待确认/可抓/选中/暂时遮挡/已取走/失败）。RGB看到但深度无效时仍建二维待确认记录，不伪造三维距离或抓姿。

按时间戳使用 T_odom_target = T_odom_chassis × T_chassis_armbase × FK(q) × T_tool_camera × p_camera。移动底盘后必须使用新位姿；车身起伏/坡度需要完整姿态。没有可靠里程计时只做停车扫描，并在车辆每次移动后重新关联，不能声称实现跨移动永久编号。

同帧检测与已有目标做一对一匹配，结合三维距离、不确定度、类别与外观；相同颜色不能直接合并，检测顺序不是编号。失去视野保留记录；重新出现需验证关联。关联歧义时不强行承接旧身份。

“最近”定义为目标相对底盘的水平距离，不能用图像大小或相机光轴深度替代。优先最近的已确认且存在可通行停靠位置的目标；距离未知的先补观测，最近但不可达的说明原因并保留。选中后锁定ID，不能每帧因距离小幅变化切换目标。窗口显示所有ID、距离、状态，突出当前目标，提供人工点选覆盖。

移除单目标入口限制时，显式传入 selected_target_id 和对应候选；保留其他物块的点云作为障碍。不能简单取 proposals[0]，也不能删掉其他检测以假装只有一件。

## 机械臂探索范围

用户后续示教扫描关键帧及允许连线，组成可往返路径图；默认只沿确认过的边插值，不任意连接两个“安全端点”。端点安全不证明中途扫掠安全。探索视野跟踪仅允许在该图及验证过的小范围偏置内进行。

有限跟踪以目标投影落在画面中心区域为目标，允许一定偏离，避免追逐像素噪声。到扫描边界时请求底盘转向/停车重定位，不突破机械臂探索范围。放料示教路径与探索路径分开管理，不能用放料关键帧当扫描限位。

## 最适合抓取的停靠位置

不是统一设置相机距离。采样目标周围的候选底盘位置与朝向，检查通行空间、目标可见性、机械臂可达性、关节余量、完整接近与撤离路径，再从可行点中选移动少、姿态舒展、观测较好的点。由当前装车高度、90mm近似TCP与实测成功抓取工作区确定首版停靠范围，不先拍定数值。

移动期间RGB跟踪用于保持视野和验证目标身份，深度可靠时更新相对距离。目标遮挡/ID不确定时停车重观测；有障碍地图时才绕行，不盲目朝框中心开。停车后重新解算抓取坐标，废弃移动前抓取解。最终伸臂阶段锁定静止目标，允许相机近场丢失视野，不要求不断重识别才能完成下降。

## 底盘接口

依据原车 docs/real_chassis_test.md 与 lower_controller_contract.md：自主速度经 /navigation/chassis_cmd_vel → nav_to_manual_mux → /manual_control → motion_solver → H7 USB CDC。历史 /chassis/cmd_vel 调试链路不是当前实车最终入口，不能同时控制同一底盘。

探索模块输出底盘坐标下的期望速度/停车请求，由已有仲裁与运动解算发送下位机；不能另开串口绕过仲裁。需核实当前部署的定位、停车反馈、导航和避障是否可用。手眼标定不等于机械臂底座到底盘的安装外参，该变换也需确认。

## 实施与验收顺序

1. 固定底盘：多目标编号、选择最近目标、人工切换、选中一件抓取；保留原分步操作。
2. 示教扫描：移动腕部后同一物块ID保持，遮挡重现正确关联，限位外不生成运动。
3. 整车影子运行：仅显示期望停靠点/速度，不发送运动，核对方向和距离。
4. 接通底盘：有限跟踪、停车重观测、抓取及示教放块返回，再处理下一件。

记录ID切换次数、重复目标数、覆盖的扫描区域、停靠误差、目标丢失、抓取/入仓结果。必测多个同色物块、交叉遮挡、RGB有效但深度缺失、底盘移动后重现、扫描边界目标、最近目标不可达。当前未实现或实机验收上述能力。
